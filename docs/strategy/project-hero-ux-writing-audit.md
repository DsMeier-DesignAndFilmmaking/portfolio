# Project Hero UX Writing Audit

Review lens: UX writing and editorial clarity only.

Goal: reduce reading effort without reducing meaning. The hero should invite the visitor into the project, not summarize the whole project.

This document provides recommendations only. It does not rewrite full pages or create marketing copy.

## Evaluation Criteria

- Headline clarity.
- Supporting paragraph length and effort.
- Label and metadata usefulness.
- Caption necessity.
- Visual text burden.
- Repeated terminology.
- Generic or inflated language.
- Over-explaining.
- Passive or weak openings.

## Cross-Portfolio Writing Issues

### Repeated Concepts

- "Confidence" appears across many pages and remains valuable, but it risks becoming a default explanation for every system.
- "Adaptive," "context," "signals," "recovery," "guidance," "system," "framework," and "architecture" recur heavily.
- Several pages repeat the same structure: concept name, system type, live signals, changing conditions, human agency.
- Many heroes repeat the page's deeper thesis before the visitor has entered the case.

### Repeated Terminology

- "Concept architecture"
- "In Research & Development"
- "Prototype Phase"
- "Environmental systems"
- "Decision support"
- "Live context"
- "High-confidence"
- "Human-centered"
- "System logic"
- "Middleware"

Recommendation: keep technical terms, but ration them. The hero should usually contain one technical term at most, then let the body section expand the vocabulary.

### Buzzwords And Inflated Language

- "Human-centric"
- "High-fidelity UX/UI design phase"
- "Headless intelligence layer"
- "System-level intervention"
- "Fiduciary executor"
- "Autonomous orchestration"
- "Semantic translation"
- "Decision vectors"
- "Travel DNA"
- "Knowledge affinity"

Recommendation: move most specialized terminology below the fold unless the term is the project's actual object of study.

### Generic Language

- "Improving user experience"
- "Modern design"
- "Streamlined navigation"
- "Engaging digital experiences"
- "Innovative technology solutions"
- "Data-driven decisions"
- "On-brand digital experiences"
- "Human-centered experiences"

Recommendation: replace generic outcome language with the specific proof of work: IA, audit, prototype, product discovery, conversion path, CMS, component system, kiosk flow, service recovery, or trust layer.

### Over-Explaining Patterns

- Challenge/Solution/Core Pillars in the hero.
- Scenario metadata above the fold.
- Full captions attached to already-labeled visuals.
- Multiple badges explaining maturity and status.
- Long supporting paragraphs that include origin, mechanism, audience, and future use.

Recommendation: the hero should answer one question: "What is this project about?" The next section can answer "Why does it matter?" and "How does it work?"

## Label, Metadata, Caption, And Visual Text Guidance

### Keep Above Fold

- Breadcrumb or one short eyebrow.
- Project title.
- One status note only when status prevents misunderstanding.
- One concise supporting sentence.
- One CTA only when the next action is meaningful.

### Remove Above Fold

- Surface_ID.
- Multiple status badges.
- Tag clusters.
- Full figcaptions.
- Challenge/Solution/Core Pillars.
- Scenario metadata.
- Ownership labels.
- Repeated labels inside visual artifacts.

### Relocate Below Fold

- Evidence boundaries.
- Detailed system diagrams.
- Research inputs.
- Operating model descriptions.
- Technical architecture labels.
- Vendor/integration details.
- Metrics and proof points.
- Expanded captions.

## Recommended Hero Copy Pattern

Use this pattern as an editorial guardrail:

1. Name the project.
2. Say what it helps clarify, decide, or experience.
3. Stop.

Example structure:

- Eyebrow: Project category or status.
- Headline: Project name or strongest plain-language title.
- Supporting copy: One sentence, 18 to 28 words.
- Optional note: One short evidence/status boundary.

## Writing Priorities

1. Shorten Travel + AI logic heroes first.
2. Remove repeated metadata from product surface heroes.
3. Replace generic client-work descriptions with specific proof.
4. Collapse duplicated summary/thesis/callout copy on research pages.
5. Move technical vocabulary below the fold unless it is the project's primary name.

## Final Editorial Principle

The hero should create confidence by sounding finished, not exhaustive. Use the first viewport to establish what the work is. Use the rest of the page to prove how deeply it was thought through.
