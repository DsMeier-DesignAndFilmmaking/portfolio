# Project Hero Audit

Design review focused on information architecture, visual hierarchy, cognitive load, and above-the-fold strategy for the portfolio project heroes.

This is not a portfolio critique. It is an implementation-ready hero simplification strategy.

## Review Goals

- Reduce cognitive load.
- Increase clarity.
- Increase perceived professionalism.
- Improve first impressions.
- Preserve technical depth while simplifying the first viewport.
- Encourage scrolling instead of explaining the entire project in the hero.

## Legend

- Critical: Must be understood immediately.
- Important: Supports comprehension and positioning.
- Supporting: Useful, but not required above the fold.
- Unnecessary: Adds avoidable density above the fold.

## Recurring Issues

The main recurring issue is framework compression: many heroes try to prove the system, define the concept, explain the thesis, show the architecture, label maturity, and teach the visitor how to read it all at once.

Other recurring issues:

- Duplicate summary, thesis, and callout copy.
- Status tags competing with project identity.
- Diagrams that require interpretation before the visitor knows why the project matters.
- Generic archived-client descriptions that undersell real credibility.
- Long technical phrases in hero copy before plain-language value is established.
- Several heroes use proof artifacts as the first read instead of the second read.

## Recurring Strengths

- Strong project names.
- Credible systems thinking.
- Rich visual artifacts.
- Consistent evidence-boundary language.
- Strong ability to connect research, service design, product logic, and implementation thinking.
- Best heroes already point toward the right model: title, clear premise, one strong visual.

## Highest-Impact Improvements

1. Move Challenge, Solution, and Core Pillars out of heroes and into the first content section.
2. Limit each hero to one primary visual idea.
3. Replace tag clusters with one compact eyebrow/status line.
4. Shorten hero copy to one high-confidence paragraph.
5. Let scroll reveal depth instead of front-loading it.
6. Convert hero diagrams from "explain the system" to "signal the system."
7. Make archived client heroes more specific by leading with proof, role, or outcome rather than broad project descriptions.

## Implementation Priority

4. Archived client page copy sharpening.
5. Field Notes and Digital Executor polish.

## Recommended Global Hero Standard

Use this as the target model for most project pages:

1. Eyebrow or breadcrumb.
2. Project title.
3. One short positioning sentence.
4. Optional one-line evidence boundary or status note.
5. One visual, if it can be understood without reading labels.
6. Scroll cue or visible hint of the next section.

Avoid placing all of the following in the same first viewport: status badges, thesis callout, summary paragraph, tags, diagram, figcaption, challenge, solution, core pillars, scenario metadata, and CTA cluster.
