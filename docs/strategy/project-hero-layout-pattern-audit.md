# Project Hero Layout Pattern Audit

Review lens: structural layout only.

Goal: determine whether each current hero layout is the strongest possible solution for a premium case-study portfolio, then recommend a standardized layout system for the whole portfolio.

This document does not recommend code changes. It provides layout strategy only.

## Layout Options

- **Option A: Editorial left / visual right**  
  Best for case studies where a concise project premise benefits from one supporting artifact.

- **Option B: Centered editorial**  
  Best for text-led concepts, early-stage explorations, and pages where calm authority matters more than immediate proof.

- **Option C: Large full-width visual**  
  Best for client work, visual proof, product screenshots, places, or strongly photographic projects.

- **Option D: Editorial with visual below**  
  Best when the project needs a calm first read before a complex diagram, interface, or artifact appears.

- **Option E: Magazine-inspired**  
  Best for expressive, editorial, place-based, or conceptually rich work where atmosphere and pacing matter.

- **Option F: Research publication**  
  Best for frameworks, research systems, methods, evidence maps, and concept architecture where credibility comes from structure and restraint.

## Layout Pattern Ranking

### 1. Option D: Editorial With Visual Below

Best overall pattern for the portfolio's most complex independent research and Travel + AI logic pages.

**Why it ranks first:** It creates calm before complexity. It allows the visitor to understand the project in language before confronting diagrams, UI states, or system artifacts.

**Best for:** Responsive Ecologies, HADE, Spontaneity Engine, Social Capital Orchestrator, other dense logic pages.

### 2. Option C: Large Full-Width Visual

Best pattern for archived client work and visual proof.

**Why it ranks second:** Client work benefits from immediate credibility, recognizable brands, screenshots, and artifacts. These pages do not need the same conceptual ramp as research pages.

**Best for:** Purdue, TimberTech, Healthcare, McDonald's Kiosk, Intel, Nodalytics, Newdea, DoubleGood, AdviseStream, Sphere Software, Havas, Rich Products.

### 3. Option F: Research Publication

Best pattern for frameworks, research systems, and concept architecture.

**Why it ranks third:** It matches the seriousness of the work and prevents research pages from feeling like product demos. It should be used selectively so the portfolio does not become too austere.

**Best for:** Environmental Systems Design OS, Architecture of Confidence, Trust Framework, CATDS, Relational Heuristics.

### 4. Option A: Editorial Left / Visual Right

Useful but currently overused.

**Why it ranks fourth:** It is familiar, flexible, and efficient, but it becomes a problem when the right-side visual is too dense. It should be reserved for pages with one simple visual artifact.

**Best for:** Adaptive Outdoor Hospitality Companion and product surface pages.

### 5. Option E: Magazine-Inspired

Best for expressive and place-based projects, but not a universal system.

**Why it ranks fifth:** It can produce the most premium feeling when used well, but it requires more editorial restraint and visual sensitivity.

**Best for:** Intention Engine, Wayfinding Matrix, Narrative Architecture, possibly Narrative Experience Generator.

### 6. Option B: Centered Editorial

Useful for quiet early-stage or text-led pages, but too minimal for the whole portfolio.

**Why it ranks sixth:** It creates calm, but can feel under-evidenced if used too often.

**Best for:** Field Notes, Digital Executor, transitional or early-stage concept pages.

## Recommended Standardized Layout System

Use a three-family layout system rather than forcing every project into one hero template.

### Family 1: Research And Framework Pages

**Default pattern:** Option F, with selective Option D.

**Use for:**

- Environmental Systems Design OS
- Architecture of Confidence
- Trust Framework
- CATDS logic
- Relational Heuristics Engine

**Structure:**

1. Breadcrumb or small eyebrow.
2. Project title.
3. One-sentence abstract.
4. Optional evidence/status boundary.
5. No dense diagram in first read.
6. Diagram/model begins below the fold.

**User impact:** Greater seriousness, stronger perceived rigor, lower reading effort.

### Family 2: Concept And Experience Pages

**Default pattern:** Option D or Option E.

**Use for:**

- Wayfinding Matrix
- Intention Engine
- Responsive Ecologies
- HADE
- Narrative Architecture
- Social Capital Orchestrator
- Field Notes
- Digital Executor

**Structure:**

1. Editorial opening.
2. One restrained image, visual cue, or no visual.
3. Complex visual proof below the fold.
4. Atmosphere before explanation.

**User impact:** More premium, less crowded, stronger invitation to scroll.

### Family 3: Client And Product Proof Pages

**Default pattern:** Option C for client work, Option A for product surfaces.

**Use for:**

- Archived client work
- Travel + AI product surface pages

**Structure for client work:**

1. Full-width visual.
2. Breadcrumb.
3. Client/project title.
4. One proof sentence.
5. Details and metrics below.

**Structure for product surfaces:**

1. Editorial left.
2. One short product premise.
3. Visual right.
4. Technical metadata below.

**User impact:** Fast credibility, clearer artifact recognition, stronger professional validation.

## Final Recommendation

Do not standardize on a single visual arrangement. Standardize on a decision system:

- **Research-heavy pages use Research Publication.**
- **Complex concept pages use Editorial With Visual Below.**
- **Atmospheric/place-based pages use Magazine-Inspired.**
- **Client proof pages use Large Full-Width Visual.**
- **Product surface pages use Editorial Left / Visual Right.**
- **Early or text-led concepts may use Centered Editorial.**

This preserves variety while making the portfolio feel governed by one editorial intelligence. The strongest overall move is to stop using dense right-column diagrams as the default proof mechanism. Let the hero establish trust first; let the next section carry the complexity.
