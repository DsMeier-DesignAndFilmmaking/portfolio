# Project Hero Visual Hierarchy Audit

Review lens: visual hierarchy only. This ignores code quality, business strategy, routing, and content completeness.

Goal: hero sections should feel calm, premium, intentional, and confident through restraint. The first viewport should create a clear first read, a controlled second read, and an obvious reason to continue scrolling.

## Scoring Key

- Visual hierarchy: clarity of primary, secondary, and tertiary reads.
- Editorial quality: how composed, paced, and publication-ready the hero feels.
- Professional polish: perceived finish, restraint, and trustworthiness.
- Whitespace: breathing room, density control, and text/visual spacing.
- Balance: relationship between text, image, diagram, grid, and viewport.
- Overall clarity: how quickly the visitor understands what to look at and why.

## Cross-Portfolio Visual Hierarchy Findings

### What Immediately Attracts Attention

- Large diagrams and interface mockups often attract attention before the project title.
- Dark client-work hero images create fast credibility and are generally effective.
- Long technical titles attract attention, but not always in a helpful way.
- Badges, tags, and uppercase labels are visually louder than their importance warrants.

### What Competes for Attention

- Tag clusters compete with project identity.
- Figcaptions compete with primary supporting copy.
- Interactive diagrams compete with the editorial headline.
- Challenge/Solution/Core Pillars blocks compete with the hero itself.
- Multiple CTAs create unnecessary decision weight.

### Where the Eye Becomes Confused

- When a diagram contains many labels before the visitor knows the thesis.
- When the title, subtitle, thesis callout, and summary all communicate similar ideas.
- When right-column visuals contain multiple small UI states, badges, tabs, and labels.
- When metadata such as Surface_ID is presented in the same visual zone as project identity.

### Where Hierarchy Collapses

- Travel + AI logic detail heroes collapse most often because they compress an entire case-study overview into the hero.
- Responsive Ecologies and Wayfinding Matrix collapse because their visuals explain too much.
- Intention Engine nearly works, but layer tiles and figcaption pull it away from calm editorial impact.
- Client pages mostly avoid hierarchy collapse, but some lose editorial quality through generic copy.

### Components That Feel Visually Heavy

- Interactive system diagrams.
- Full executive-summary blocks in the hero.
- Multi-step flow cards.
- Tag clusters and badge rows.
- Dense right-column mockups.
- Long titles with technical subtitles.
- Figcaptions attached to already-labeled visuals.

### Components That Feel Unnecessary Above The Fold

- Surface_ID.
- Full Challenge/Solution/Core Pillars sections.
- Scenario metadata.
- Multiple tags.
- Multiple badges.
- Diagram figcaptions.
- Ownership labels.
- Second CTAs unless there is a strong conversion need.

## Implementation-Ready Visual Hierarchy Improvements

1. Establish a strict first-read rule: project title must be the most obvious element in every hero.
2. Limit each hero to one secondary read: either a subtitle, a positioning sentence, or a visual. Avoid all three competing at full weight.
3. Reduce metadata to one small eyebrow line.
4. Move tags below the fold unless they are essential to disambiguation.
5. Move Challenge, Solution, Core Pillars, and scenario metadata into the first body section.
6. Use diagrams in the hero only when they can be understood as a single shape or mood.
7. Convert dense hero visuals into quieter preview states.
8. Remove figcaptions from the first viewport when the visual already includes labels.
9. Use one CTA maximum in hero sections.
10. Increase vertical breathing room between headline, support copy, and visual.
11. Make right-column visuals optically lighter than left-column title blocks.
12. Prefer one large focal point over several small proof points.

## Recommended Premium Hero Pattern

Use this structure for most project pages:

1. Small eyebrow or breadcrumb.
2. Large title.
3. One calm positioning sentence.
4. Optional one-line status or evidence boundary.
5. One quiet visual or image.
6. Hint of next section.

The hero should not prove everything. It should make the visitor feel that the work is composed, credible, and worth scrolling into.
