*The strategic operating model — the whole practice as one system, and how value flows through it.*

---

## The core idea

The fourteen layers are not a waterfall. They are a **compounding loop**. Value flows *down* as enablement (each layer makes the next possible) and *back up* as return (evidence, revenue, authority, and fresh observation). The bottom layer — Field Research — feeds the top, closing the cycle. Each full turn of the loop leaves the frameworks more validated, the corpus larger, the authority higher, and the practice able to charge more and reach further.

Two rules govern the whole system:

- **Nothing monetizes until it is proven.** Value can only reach the capture layers (products, consulting, speaking, publications, open source, education) *after* it passes through Client Work. This is the red-team rule as a structural invariant — the ecosystem is physically unable to sell what it hasn't validated.
- **The loop must close to compound.** If revenue, authority, and observation don't return to the top, the system is a pipeline that runs once, not an ecosystem that grows.

## How value flows between the layers

Every adjacent relationship carries a **downward** flow (what the upper layer enables) and an **upward** flow (what the lower layer returns).

| Between | Flows down — enablement | Flows up — return |
|---|---|---|
| Practice ⇄ Field Research | The lens: *what is worth observing, and how* | Ground truth that keeps the practice honest and specific |
| Field Research ⇄ Research Themes | Raw patterns that reveal which questions matter | Focus — themes direct where to observe next |
| Research Themes ⇄ Frameworks | The questions a framework must answer | Durable IP that gives a theme standing and citation |
| Frameworks ⇄ Projects | A reusable model to instantiate and test | Stress-tests, edge cases, and *new* frameworks surfaced |
| Projects ⇄ Applications | A concept to apply in a specific domain | Proof of transfer; the concrete artifact a buyer can see |
| Applications ⇄ Client Work | A ready application to run in a real setting | **Validation + revenue + a case study** (the pivot point) |
| Client Work ⇄ Capture layer | Proven IP that has *earned* the right to be sold | Revenue, authority, reach, adoption — the returns that fund and attract |

**The capture layer fans one proven framework into six currencies**, each returning something different:

- **Consulting Services** → the highest near-term revenue, *and* fresh field observation (every engagement is a field study — work-emits-research).
- **Future Products** → leverage: revenue decoupled from the founder's hours.
- **Publications** → authority and findability; the asset that compounds longest and makes everything else citable.
- **Speaking** → reach and relationships that convert into consulting leads.
- **Open Source** → adoption and credibility, plus a contributor community that feeds new observation back to Themes.
- **Education** → scale and a new revenue tier, and evangelists who carry the frameworks outward.

## The compounding loops

What makes it an ecosystem rather than a pipeline is that four loops feed the top:

1. **The proof loop.** Client Work validates a framework → the framework's maturity rises → it earns access to the capture layer → capture revenue funds more validation. *(This is the loop currently stalled — see below.)*
2. **The authority flywheel.** Publications + speaking + open source raise authority → authority attracts better client work and bigger stages → better work makes richer publications. Its fuel changes over time: point-of-view first, validated case studies second, others citing you third (thought-leadership).
3. **The observation loop.** Consulting, education, and open source each generate *new* field observation and community signal → which feeds Research Themes → which sharpens Frameworks. The system learns from its own outputs.
4. **The revenue loop.** Capture-layer revenue funds Field Research documentation and product builds → which strengthen the intake and the leverage → which raise future revenue.

---

## The proof gate — the system's single constraint

One rule sits across the middle of the map: **no framework reaches the capture layer without passing through Client Work.** A framework cannot skip from the shelf to a product, a course, or a certification without a validating engagement first. This is the structural encoding of the practice's own discipline (and the same guardrail designed into `practice-narrative-architecture.md`, where services are terminals of proof chains). It is what keeps the ecosystem from becoming an elaborate output machine with nothing proven underneath it.

---

## Current-state diagnosis — where the value actually is

Read honestly, the map shows a system that is **rich above the proof gate and nearly empty below it.** The intellectual layers (Themes, Frameworks, Projects, Applications) are dense and well-developed. The capture layers (products, consulting, speaking, publications, open source, education) are almost all latent. And two valves are nearly shut:

- **The intake valve:** Field Research is a genuine moat but is *undocumented*, so it cannot yet flow into citable frameworks.
- **The proof gate:** there is **no current client engagement**, so almost no value is passing from Applications into the capture layer. The whole downstream ecosystem is dammed at one point.

The strategic consequence is unambiguous and matches every other doc in the corpus: **the entire ecosystem is gated on a single event — one validated engagement.** Push one application (Adaptive Hospitality is the warmest) through the proof gate, and it opens all six capture flows at once — a case study to publish, a talk to give, a service to sell, a product to justify, a course to teach, and fresh observation to feed the top. Everything upstream is already built; the system is waiting on the first turn of the loop.

---

## Using this as the operating model

- **Locate any activity on the map before starting it.** Know which layer it sits in, what feeds it, and what it must return. An activity that returns nothing to the loop is a leak.
- **Never build a capture surface ahead of its proof.** A course, product, or certification whose framework hasn't passed the proof gate is the system running backwards.
- **Measure the practice by loop closure, not output volume.** The health metric is not "how many docs / concepts / surfaces exist" — it is *how much revenue, authority, and observation returned to the top this cycle.* By that measure the practice is pre-first-turn, and the one move that starts the flywheel is the first validated engagement.
