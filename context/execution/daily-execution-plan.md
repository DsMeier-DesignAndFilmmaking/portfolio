# Daily Execution Plan

## Core Constraint
1–2 hours per day maximum. Every minute spent overbuilding is a minute not spent shipping or connecting.

---

## Daily Structure (90-Minute Default)

### Block 1 — Portfolio Work (30 min)
**Goal:** One concrete improvement to the case study or positioning. Not a full rework. One thing.

Rotation:
- Monday: HADE system diagram refinement
- Tuesday: Case study copy edit (one section)
- Wednesday: Add or improve one constraint documentation
- Thursday: Logic receipt or trust layer visual
- Friday: Review full portfolio against evaluation rubric — score it

**Rule:** Do not start new sections until existing sections score 4+ on the evaluation framework.

---

### Block 2 — Applications (30 min)
**Goal:** 2–3 targeted applications per day. Not more.

**Per application:**
1. Read the job description carefully (5 min)
2. Identify the specific product problem they are hiring for (2 min)
3. Write one tailored paragraph connecting HADE or a specific project to their problem (10 min)
4. Submit with that paragraph as the cover or intro message (3 min)

**Hard limit:** No more than 3 applications per day. Quality over volume. A generic application is worse than no application — it burns a contact.

---

### Block 3 — Networking (30 min)
**Goal:** 2–3 outreach messages per day. Conversations, not job requests.

**Per message:**
1. Identify the person and their specific work (3 min)
2. Find one genuine observation about their product, writing, or company (2 min)
3. Write a short, direct message — reference the observation, ask one question (5 min)
4. Send it (1 min)

**Rule:** Never ask about job openings in the first message. The goal is a conversation, not a transaction.

---

## Weekly Output Goals

| Output | Target |
|--------|--------|
| Portfolio improvements | 5 (one per day) |
| Applications submitted | 10–15 |
| Outreach messages sent | 10–15 |
| Follow-up responses sent | All within 24 hours |
| Case study scored against rubric | Once per week (Friday) |

---

## Packaging Over Overbuilding

**The trap:** Spending 3 hours refining the HADE animation instead of documenting the system decision that makes HADE interesting.

**The rule:** If it takes longer than 30 minutes and it's not a core decision documentation task, it's overbuilding.

What gets packaged (high value):
- System diagram with labeled inputs, logic, outputs
- Constraint documentation (what couldn't you do, and why)
- Decision rationale (what did you reject and why)
- Iteration evidence (what broke, what changed)

What gets deprioritized (low value for hiring):
- Animation polish
- Color and typography refinement
- Adding more case studies before existing ones score 4+
- Building new features on the portfolio site

---

## Weekly Review Checklist (Friday, 15 min)

- [ ] Did I submit 10–15 applications?
- [ ] Did I send 10–15 outreach messages?
- [ ] Did I make 5 concrete portfolio improvements?
- [ ] Did I score the HADE case study against the rubric?
- [ ] What is the one thing that would have the highest impact next week?
